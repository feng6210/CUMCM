# 国奖与优秀论文的叙事—图表蒸馏

## 来源范围与使用边界

本参考来自对一份 98 页国奖扫描论文的逐页检查，以及对本地 2021、2022、2024 年 A--E 类 11 份优秀论文样本的首页、正文关键节点、结尾和附录横向复核。2024 年样本之一只有部分页面，因此只用于识别局部叙事和视觉模式，不用于判断全文完整性。样本标签、获奖身份和页面呈现不等于每个做法都正确。

这些样本是设计证据，不是可复制文本、模型答案或获奖保证。Skill 运行时不读取原始本地目录；只有下述已蒸馏规则进入工作流。遇到本题证据与样本经验冲突时，以题目、真实结果和验证证据为准。

2026-09-08 的补充蒸馏依据既有阅读台账：本地159个文件/逐页图片集合条目中88项摘要至正文结尾/参考文献已读、2项缺页只读可用部分，另有1篇联网取得正文已读；实际查看参考图页455页。条目并非已去重的159篇国奖论文，阅读正文不等于逐式、逐数及全部附录代码认证；这些计数是历史阅读边界，不是本次重新阅读全文或 Skill 泛化通过证明。包内不分发原论文，也不要求运行时访问原目录。

新增阅读和实用修订所得的通用方法见 [论文可读性与修订闭环](../../../mm-paper-structure-writer/references/paper_readability_and_revision.md)。来源台账应区分官方展示、作者自述、本地标签、草稿/缺页，以及文字提取、实际阅读和实际看图范围；目录名与 OCR 成功不认证奖项或阅读完成。

## 一、论文首先是一条依赖链

优秀数模论文通常不是若干独立小论文的拼接，而是：

```text
题目要求
→ 分问依赖图
→ 共享数据/几何/动力学/评价内核
→ 问题一校准或建立基础量
→ 后续问题增加变量、约束或决策层
→ 统一验证与适用边界
→ 摘要和结论回收每问事实
```

写作前建立 `NARRATIVE_MAP.yaml`：

```yaml
paper_thesis: 论文要解决的总矛盾，而不是模型名称列表
question_dependency_graph:
  - from: Q1
    to: Q2
    transferred_objects: [参数, 状态量, 数据版本, 几何关系]
    data_or_parameter_version: 传递对象的冻结版本
    uncertainty_transfer: 误差如何继续传播
independent_questions:
  - question_id: Q4
    independence_reason: 若无依赖，说明为何可以独立求解
shared_kernel:
  purpose: 多个分问共同依赖的建模核心
  equations_or_rules: [关键方程或规则编号]
  introduced_in: 模型准备或第一个相关章节
question_arcs:
  - question_id: Q1
    task_and_difficulty: 本问输出及真正困难
    inherited_objects: []
    new_objects: [本问新增变量、约束、目标]
    model_delta: 相对共享内核新增什么
    solver: 求解或推断路径
    exact_result_location: 精确结果表或机器可读结果
    validation: 检验或稳健性证据
    claim_boundary: 允许写到什么程度
```

若各问确实独立，可以不强行建立共享内核，但必须在 `independent_questions` 中写明独立理由。

## 二、推荐的正文叙事节奏

### 1. 摘要专页是压缩后的答案表

首句只交代总任务和必要背景。之后按分问顺序，每问用一个完整事实单元：

```text
针对什么输出
→ 建立了什么本题化结构
→ 如何求解
→ 得到哪个关键数值/方案
→ 经何种检验
→ 结论边界是什么
```

模型名只在区分方法或解释创新时出现；不得把算法名称串联成摘要。精确数值优先来自最终结果表，不能从图上目测抄写。

### 2. 问题分析不是重复题目

问题重述负责准确改写任务；问题分析负责回答：

- 数学对象是什么；
- 难点来自数据、几何、随机性、动态性还是约束耦合；
- 本问需要继承前文什么；
- 先算什么、后算什么；
- 哪个结果会进入下一问；
- 最终用什么证据判定模型可用。

多问存在依赖时，优先给一张低装饰的关系图；图中节点必须对应实际章节和工件，不得添加正文不存在的流程。

### 3. 共享内核只讲一次

多个分问复用坐标系、运动学方程、数据变换、指标体系或评价规则时，在“模型准备/共享模型”集中定义。后续章节只说明：继承对象、增加对象、改变约束、改变目标和误差传播。不得为增加篇幅重复推导同一公式。

### 4. 每问覆盖论证要素，不固定六段

```text
任务与难点
→ 本问变量/输入/继承关系
→ 模型增量与约束
→ 求解步骤及停止条件
→ 精确结果与图形证据
→ 检验、解释和声明边界
```

一个模型章节不应在给出算法流程图后直接跳到结论。至少要有机器可读结果定位、求解状态、约束/误差重算或模型专属检验。

上述是内容覆盖顺序，不是强制六个段落或固定句式。解析或定性问题按其证据形式组织；已在共享章节定义的内容不重复。主要结果图后解释观察、模型内机制、设计含义与边界，不把审计文件名当作读图解释。

### 5. 章节之间要有交接句

每问末尾说明哪些输出将被下一问复用、复用的是点估计还是区间、适用场景是否改变。只有确有依赖时才写交接，不能用空泛“为下一问奠定基础”。

### 6. 结尾不重复摘要

模型评价针对本题写：捕捉了什么机制、在哪些数据/条件下成立、遗漏什么、计算代价如何、推广需要新增什么证据。避免“精度高、适用性广、操作简单”等无对象套话。

## 三、图表承担四种不同角色

### 1. 导航图 `orientation`

用于分问依赖、总体求解链或必要场景说明。全文通常只需少量。它帮助读者知道“先后关系”，不承担数值结论。

### 2. 机制图 `mechanism`

用于坐标系、几何关系、受力、状态转移、约束区域或真实算法分支。机制图应像证明的一部分：

- 图中实体、符号、角度、坐标和边界与公式完全同名；
- 几何关系能从图走到方程，方程也能回指图中对象；
- 算法流程包含输入、关键分支、停止条件和输出；
- 同一实体跨图保持名称、符号、形状和方向一致；示意图用黑白线型编码，彩色结果图内保持颜色一致，不要求跨两类图使用相同颜色。

### 3. 证据图 `evidence`

用于原始数据、预处理效果、拟合、方案比较、轨迹和权衡，回答“结果呈现出什么结构或差异”。

### 4. 验证图 `validation`

用于残差、约束余量、收敛、敏感性和极端情景，回答“结果是否满足模型专属检验”。证据图和验证图推荐形成可阅读的证据对：

```text
原始 → 处理后
基线 → 主模型
名义参数 → 扰动参数
拟合/预测 → 残差/误差
目标值 → 约束余量
```

只有一个图不能同时完成“展示趋势、给精确答案、证明稳健性”三件事。表格承载精确数字，图承载形状、关系、权衡和稳定性。

## 四、图表选用与版面规则

- 每张图必须绑定一个分问、一个 `claim_id` 或一个不可替代的解释任务；否则删除。
- 正文先给图表预算，再按证据需要增减，不设固定张数。重复图和低价值参数遍历放附录。
- 小多图必须共用可比尺度、清晰标注子图、在论文最终宽度仍可读。正文常规优先 2--4 个面板；超过 4 个需说明不可拆分理由，超过 6 个优先移入附录。
- 真实空间、双参数响应或三维轨迹可采用三维与二维组合；给投影、切片、关键点或精确表，避免视角遮挡，不要求先证明二维完全不能用。
- 流程图展示真实计算逻辑，不画装饰性“数据输入—建立模型—得到结果”空框链。
- 定量图可用 Origin、MATLAB、Matplotlib；几何/物理图默认 TikZ，可按用户选择用 Visio 或其他真实可编辑后端。原生源与 XeLaTeX 用 PDF 同存并重开验证，不伪造原生文件。
- 配色按当前用户要求区分：示意图默认黑线黑字白底，以虚实线、线宽与剖面线区分；结果图可使用鲜明配色和非误导性装饰。保证同实体符号一致和最终尺寸可读，不把示意图的黑白规则扩展为结果图少色门。
- 图内不放论文式标题；轴名必须含中文变量名与单位。长解释放中文图题，精确结果放表格。
- 结果表保留决定答案的变量、目标值、约束余量和必要精度；图表与表格若表达完全相同的信息，只保留更清楚者。

## 五、从优秀论文中也要拒绝的做法

- 把软件界面、代码窗口或低分辨率截图直接作为定量证据图；
- 把很多小图压在一页，导致轴字、图例和标记在最终尺寸不可读；
- 默认 Excel/Matlab 彩虹色、巨大图例、过多系列和无语义配色；
- 用 3D 柱状图、双纵轴或弦图制造复杂感，却没有独特读者任务；
- 流程图没有输入、条件、终止和输出，只是章节目录的图形化；
- 用图上目测值代替结果文件，或图表和精确表格数值不一致；
- 每问重新讲一遍共享模型，造成叙事断裂和页数浪费；
- 附录只贴代码截图，没有文件列表、入口、配置、数据版本和运行说明；
- 因“优秀/获奖”标签而照搬少量引用、模糊图题或缺失验证。

## 六、写作和审稿的强制问题

在锁定摘要和结论前逐问回答：

1. 本问的精确答案放在哪里，能否从机器可读结果重算？
2. 本问相对共享内核新增了什么，而不是采用了什么响亮模型名？
3. 图形是在解释机制、显示证据还是验证稳定性？
4. 如果删除该图，哪个判断会变得不可理解？若没有，为什么保留？
5. 结果表、图题、正文和摘要是否使用同一口径与精度？
6. 章节末尾是否明确了下一问继承对象和不确定性？
7. “最优、提高、稳定、准确、有效”等词是否存在相应证据和范围限定？

只有全部问题能用当前工件回答，才可将叙事与图表标记为可交付。
