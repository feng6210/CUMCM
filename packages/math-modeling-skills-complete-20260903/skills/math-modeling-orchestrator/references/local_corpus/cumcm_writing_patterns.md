# 本地 CUMCM 论文样本的写作蒸馏

## 样本事实

对 2023 年目录中 14 份标注为优秀论文的 PDF 做了摘要和章节信号抽取。12 份出现问题重述、12 份出现模型假设、12 份出现符号说明、11 份出现问题分析；按保守正则，9 份摘要含明确数字结果。目录标签和文本抽取不等于对奖项、全部内容或论证质量的独立认证。

## 保留的写作模式

1. **按分问锁定叙事**：围绕当前分问的对象和困难组织模型、求解、结果与必要验证，不把多个分问写成互不相关的小论文。
2. **公式服务接口**：只写决定输入输出、约束、可复算性的公式；通用算法历史和大段教科书原理压缩或引用。
3. **结果进入摘要**：摘要事实表至少包含每问的本题化模型/关系和关键数字；验证与声明边界在会改变答案解释时进入摘要，否则保留在正文证据层。
4. **递进关系写清**：后一问继承前一问的参数、预测或结构时，明确继承内容、版本和误差如何传播。
5. **创新绑定痛点**：把改进写成“基线不足 → 结构改变 → 证据”，不写“采用先进算法所以效果好”。
6. **图表各司其职**：表格给精确结果，图形给趋势/分布/机制，正文解释真正影响结论的现象与边界；三者数字一致。
7. **共享内核只建一次**：多问复用坐标系、动力学、数据变换或评价规则时，先建立共享内核；后续分问只写继承对象、模型增量和误差传播。
8. **每问在证据层形成微闭环**：任务与难点、输入与变量、模型增量、求解与停止、精确结果、检验与声明边界都必须可追溯，但不要求在正文逐项机械展开。正文只显式保留对评委当前判断必要的验证和边界，其余集中到模型检验、模型评价或支撑材料。
9. **章节有真实交接**：后一问使用前一问的参数、状态或方案时，明确版本、口径和不确定性；没有依赖则不强行串联。
10. **图有叙事角色**：导航图说明依赖，机制图连接符号与公式，证据/验证图显示可复算结果；没有不可替代读者任务的图应删除。
11. **自然化不是另加模板**：不同分问、段落和题型由数学对象决定详略，不强制“主题句—三句解释—总结句”，也不要求每问都以免责声明收尾。
12. **读者先看答案，再看边界**：只要不改变数学含义，正文优先直接陈述模型和结果；重复的审计限定后移，不让“候选/预算内/不能声称/不代表”成为每段固定节奏。

完整的国奖/优秀论文叙事和图表蒸馏见 [award_paper_narrative_figure_distillation.md](award_paper_narrative_figure_distillation.md)。写作前必须先建立其中定义的 `NARRATIVE_MAP.yaml`，再建立图表计划。

## 需要拒绝的样本缺陷

- 摘要只列方法，没有关键结果。
- “模型表现优良”“明显提升”没有同协议基线和数值。
- 结果驱动调参后仍把测试集写成独立验证。
- 把启发式最好值写成全局最优。
- 章节标题齐全但没有与声明对应的检验证据。
- 为显得复杂而堆叠模型名称、软件名称和公式。
- 重复推导共享模型，把各分问写成互不相干的小论文。
- 每个结果后都重复“验证—限制—不能声称”，把竞赛论文写成软件 QA/科研审计报告。
- 图表过密、字号过小、软件截图、无停止条件的装饰流程图或遮挡关键关系且没有辅助投影/精确值的三维图。鲜明配色和适用的三维本身不是缺陷。

## CUMCM 中文论证要素骨架

下列内容是**证据完整性检查顺序**，不是正文模板，也不是可逐问原样替换方括号的固定句式。实际正文应根据机理、预测、统计或优化题的论证对象改变句法、段落长度和验证位置，避免每问形成机械同构文本。

```text
任务/输出
→ 当前数学对象与约束
→ 共享内核或本问模型增量
→ 求解/停止条件
→ 精确结果
→ 可追溯验证与声明边界
```

写作时优先把前五项组织成自然叙事。最后一项按决策价值放置：会改变当前答案含义时就地保留；否则放入模型检验、模型评价或支撑材料。

## 摘要事实锁定顺序

默认顺序为：

`问题与输出 → 本题化模型/关系 → 求解 → 关键数值 → 必要解释 → 关键词`。

验证只保留最有区分度且直接支撑核心答案的一项；限制仅在不写会误读答案时出现。摘要、结论和标题最后锁定，并仅引用 `RESULTS_TO_CLAIMS.md` 中 `yes/partial` 的声明。完整证据链仍保留在结果映射和正文/支撑材料中，不能通过精简叙事隐藏 FAIL 或实质性边界。
