# 结果验证协议

验证分六层，不能互相替代：

1. **语义**：目标函数、计时口径、资源复用、多目标聚合与题意一致；没有在求解后偷偷改口径。
2. **结构**：输入字段、单位、维度、缺失、范围和信息时序正确。
3. **数值**：残差、收敛、步长、容差、约束和正式目标可重算。
4. **统计/随机**：划分、区间、校准、抽样、多重比较、随机种子和 Monte Carlo 误差合理。
5. **稳健**：关键参数、权重、种子、场景或模型变化后结论不轻易翻转。
6. **对抗/外部**：与题目给定值、已知极限、独立数据、替代算法、公开可行策略或用户提供优秀论文方案在**同一 evaluator** 下比较。

## 内部稳定不等于外部最优

以下证据只说明搜索过程在当前设置下稳定：

- 多个种子落在相近目标值；
- 同一启发式多次重复得到类似解；
- 局部响应面在 incumbent 周围平坦；
- 某个离散候选库的 MILP 达到 gap 0。

它们都不能推出连续空间全局最优，也不能阻挡一个更优外部可行解。若外部策略在当前正式 evaluator 下领先超过预设容差，当前“最佳/稳定最优/近全局”声明必须降级并返回求解。

## 外部挑战记录

每个挑战填写：

`benchmark_id / source_scope / parameter_mapping / same_objective / same_physics / feasibility / recomputed_value / incumbent_value / tolerance / outcome / limitation`

其中：

- `CHALLENGED`：同口径可行且领先超过容差；
- `PASS`：没有领先超过容差，但只表示该挑战没有击穿；
- `INCOMPARABLE`：目标、物理判据、资源计数或数据协议不同；
- `NOT_ALLOWED_BY_RULES`：正式竞赛规则不允许访问外部解。

不能把原论文报告数字直接当成当前模型下的值。

## 声明卡

每个声明填写：`claim_id / source_result / semantics_ref / validation / threshold / status / limitation`。没有预设阈值时只能给探索性结论。

## 正文与支撑材料分层

- `competition_compact`：正文只保留会改变读者对模型可信度判断的关键检验；完整种子表、微小步长差、哈希、后端重开、版本谱系和高密度敏感性矩阵默认进入附录/支撑材料。
- `research_audit`：允许完整展开复现、失败证据和验证门。

优秀论文经验只能作为验证设计启发，不能替代当前题目的语义、基线和独立挑战。
