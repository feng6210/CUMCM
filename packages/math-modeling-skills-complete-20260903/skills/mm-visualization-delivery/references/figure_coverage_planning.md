# CUMCM 图表规划：先解决读者障碍，再决定是否作图

## 核心原则

图不是按分问配额生成，也不是验证报告的截图集合。正文中的每张图都必须回答一个**表格或一句文字无法同样清楚回答的读者问题**。

默认优先级：

```text
解释现实/几何/机制
> 解释策略与协同结构
> 展示需要看“形状/关系/权衡”的主结果
> 展示真正会改变结论可信度的关键验证
> 次级诊断与工程审计
```

最后一类通常进入附录或支撑材料。

## 六类读者任务不是六张图

| 读者任务 | 典型问题 | 推荐载体 | 正文规则 |
|---|---|---|---|
| `orientation` | 研究对象和分问依赖是什么 | 场景图、关系图、科研方法总览 | 分问依赖或方法链需要整体理解时主动规划 |
| `mechanism` | 从实体/几何/状态如何走到方程 | 坐标/几何/受力/case/状态图 | 复杂机理优先正文；应像推导的一部分 |
| `main_result` | 答案的结构、轨迹或权衡是什么 | 轨迹、区间、热图、Pareto、空间部署 | 若精确值表已足够且无形状信息，可不画 |
| `comparison` | 为什么主模型/方案更合适 | 基线/消融/前后对比 | 有真实竞争路线且差异需要视觉解释时画 |
| `validation` | 哪个关键检验决定是否相信结论 | 残差、约束余量、收敛、外部挑战 | 只把结论关键验证放正文；其余进附录 |
| `robustness` | 扰动后结论是否翻转 | 敏感性、情景、区间带 | 有实际决策风险或结果敏感时正文，否则附录 |

一张多面板图可以围绕**一个主要读者任务**组织若干相互依赖面板；不要为了占多个槽把同一图复制成多个图号。

## `FIGURE_INTENT.yaml` 的规划方式

`coverage_plan` 仍逐问检查读者任务，但每个任务可以由 `figure | table | text | appendix | not_applicable` 承担。只有 `representation: figure` 时才需要 `figure_ids`。

```yaml
coverage_plan:
  expected_question_ids: [Q1, Q2, Q3]
  expected_question_ids_source:
    file: QUESTION_DECOMPOSITION.json
    sha256: 64位SHA-256
    field: expected_question_ids
  questions:
    - question_id: Q1
      core_claim_ids: [claim-q1-main]
      tasks:
        mechanism:
          representation: figure
          figure_ids: [q1-geometry]
          reason: 圆柱遮蔽判据仅靠公式不易理解
        main_result:
          representation: table
          reason: 仅有一组精确起止时刻，表格更高效
        validation:
          representation: appendix
          reason: 步长与根残差均只用于数值审计，不改变主结论
figures:
  - figure_id: q1-geometry
    # 完整单图条目
```

允许的 `representation`：

- `figure`：需要真正图形；
- `table`：精确值或有限方案表更清楚；
- `text`：一句量化说明已足够；
- `appendix`：需要保留，但不值得占正文版面；若附录中仍为图，可在 `figure_ids` 中登记并将 `placement: appendix`；
- `not_applicable`：该任务不存在，必须写具体原因。

## Figure planning 与 rendering 分离

### Figure planning

在写正文前完成，回答：

1. 读者在这一段会卡在哪里？
2. 图要解释哪一个数学对象、机制、case、空间关系或结果结构？
3. 如果删除图，哪个判断会变得明显更难理解？
4. 空间结构或响应面是否适合三维加投影，哪些细节需要局部放大？
5. 这张图属于正文还是附录？

规划阶段允许没有任何输出文件，也不要求后端。

### Figure rendering

只有规划确定 `representation: figure` 后，才指定：数据来源、变量、变换、图型、后端、字体、色板、最终尺寸、可编辑文件和 PDF。渲染器不能自行新增“看起来应该有”的验证图。

## 正文图预算

不设置“每问至少 N 张”或“每个核心结论必须配图”的硬规则。复杂机理题可能一问需要 2--3 张机制/结果图，简单闭式计算可能一问零张正文图也合理。

整篇图量由以下约束共同决定：

- 读者障碍是否真实存在；
- 图是否承担不可替代任务；
- 正文页数与最终尺寸；
- 是否与表格/其他图重复；
- 是否能在附录保留完整验证证据。

图量过少时补**理解链缺口**；图量过多时优先删除/移入附录的是：完整多种子表、微小数值误差、后端审计、版本谱系、重复敏感性、没有结构信息的两柱对比。

## 机制图专项规则

优秀数模论文常见的有效视觉链是：

```text
物理场景
→ 几何/状态关系
→ 局部 case 或投影
→ 数学判据
→ 时间/空间结果
```

因此：

- 复杂几何判据应优先有 2D 机制图；
- 模型从单主体升级到多主体、多阶段或多资源时，如结构发生变化，可重新画协同/区间关系，而不是只画优化收敛；
- 算法流程图只在算法本身成为理解障碍时使用；普通“输入→建模→求解→输出”不画；
- 有真实空间或响应结构时，允许三维与投影互补；不以二维也能表达为由一律拒绝三维。

## 失败条件

- 图没有明确 `reader_takeaway`，删除后不影响任何理解或判断。
- 为满足数量规则而生成重复图。
- 复杂几何/机理只给公式和验证曲线，却没有解释关键实体关系，且 `figure planning` 无合理省略理由。
- 结果图与表格完全重复，没有趋势、结构、空间、权衡或误差任务。
- 次级数值审计挤占正文，导致主模型机制和策略难以理解。
- 三维图扭曲尺度、遮挡核心结果，或不存在真实第三维。
- 一个图号被多个任务反复“充数”，但没有清晰主任务。
